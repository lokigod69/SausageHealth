# Adversarial review · 9 September 2026

Scope: the roadmap, intake reliability, visual clarity, and readiness to share the first pilot. The existing Sausage and Loyverse projects remain read-only. This is a focused product/implementation review, not a penetration test, accounting audit, or claim to have eliminated every failure mode.

## Findings acted on

| Finding | Why it mattered | Resolution and evidence |
| --- | --- | --- |
| The roadmap named phases but omitted responsibility, acceptance and likely failure modes | A user could read “Understand” without knowing what makes the figures trustworthy | Each phase now has an owner, outcome, prerequisites, a concrete risk and response. Source uploads never automatically certify phase completion. Desktop/mobile phase controls were exercised. |
| The first intake prompts were generic across both stores | A sausage report could make the overall collection look started while health-store evidence was absent | The next action and first-sales indicators use separate store sources, the selected scope and user permissions. Shared reports don't satisfy individual-store starters. Unit tests cover this and staff self-only visibility. |
| A lost response was described as an unsaved write | Staff might resubmit a report that already reached the server | Network/invalid-response errors have an uncertain outcome. Capture keeps its submitted fields/files and request key unchanged for retries. The browser test stopped the API during a synthetic save, confirmed the retry state and locked fields, then recovered. Server idempotency already returns the same original record. |
| Expired authentication had no way to preserve an open capture | Staff could lose a long note while trying to log back in | Capture offers same-account reauthentication with the draft still mounted. The browser test expired the preview session, reauthenticated, saved exactly one record and verified byte-for-byte note equality. Expired logout also returns to the login screen. |
| Closing/reloading an unsaved form could lose the draft | A phone user might assume an attachment is saved as soon as selected | Existing close confirmation remains; a browser `beforeunload` guard now requests a warning for dirty forms. Recovery while the page stays open was exercised. This does **not** persist drafts offline or guarantee a warning on phone OS termination. |
| The text assistant's description led with receipt reading/transcription | A “TEXT BUILT” label could be mistaken for working OCR/audio | The card now describes notes/text exports, with photo and audio processing explicitly planned. No model was activated. |
| The preview required two manual server starts and had stopped overnight | The owner couldn't easily return to the workspace | `npm run start:local` validates project process identities, starts missing loopback services, probes the proxy/API, and reuses healthy listeners. Fresh start and repeat invocation passed; Windows venv parent/child identity was handled. |
| The Docker package had never been built | A successful dev preview did not establish deployable packaging | CI now builds the actual image and tests non-root operation, bundled UI, production headers/cookies, unauthorized access, original upload, retry, restart persistence, review and a backup archive. The first smoke attempt exposed an ephemeral-port assumption in the test; it now rediscovers the port after restart. [Final run passed](https://github.com/lokigod69/SausageHealth/actions/runs/34297518065). |
| Day-theme amber labels and the mobile coverage card lacked enough visual separation | Small consequential text became hard to read; the phone card squeezed its title and coverage into narrow columns | Darkened the amber action token and day-theme status text; stacked the mobile coverage card, enlarged its copy and removed overlapping decoration. The same island artwork is preserved. Desktop and mobile day/night views were inspected. |

## Remaining gates, in priority order

| Gate | What can go wrong | Required response / owner |
| --- | --- | --- |
| **Before shared launch: actual deployment** | A domain can point to the wrong app; a production environment flag does not mean TLS or isolation works | Technical owner selects the host, confirms the `ops` hostname, builds there, verifies HTTPS/cookies/private downloads and tests separate accounts. The production label deliberately says launch checks are required. |
| **Before real business intake: recovery and ownership** | An unmonitored disk fills, a volume is deleted or a backup exists only on the same server | Set a backup schedule, encrypted off-host retention, disk/failure monitoring and a responsible operator. Restore on the real target into a separate directory/volume; test originals and revoke restored sessions. CI backup creation doesn't replace this drill. |
| **Before routine phone use: real network/device test** | Long video uploads fail, HEIC files need a compatible viewer, or a browser/OS closes a draft | Test Moritz's actual phone and store network, interrupted uploads, supported file types and sizes. Use short recordings and wait for the saved confirmation. Full offline capture and background upload remain unimplemented. |
| **Before financial reporting: source semantics** | The same day is submitted twice; an ambiguous source date is treated as certain; a review checkmark is mistaken for reconciled money | Moritz records missing/ambiguous dates and duplicates in review notes and references original records when correcting. Keep source dates as reported, not verified. A typed ledger/import model must represent uncertain dates, periods, duplicate resolution and review provenance before calculations. |
| **Before live stock/reorders: identities and freshness** | kg and packs get mixed, stock transfers become sales, frozen/produced stock misses waste or yield | Verify Loyverse read-only access, ten real SKU/unit mappings, receipts/refunds and freshness; model movements, transfers, production, batch/expiry and waste. A stale read cannot support a customer promise. |
| **Before AI activation: evaluation and run versioning** | Valid quoted text still yields a wrong interpretation; a changed prompt reuses an old cached draft | Configure a provider/model/budget and evaluate representative multilingual records. Record prompt/schema versions in run/cache identity and an explicit proposal review state before treating the AI contract as complete. Current runs have source digest/model/status, but no separate prompt-version column or draft approval workflow. |
| **Before bulk imports or multiple workers: volume and migrations** | The collection fetch grows without pagination; new code creates tables but cannot safely migrate a live schema | Keep the small manual pilot bounded. Add authorized migrations and server-side pagination/filtering before bulk ingestion; load-test realistic volumes. A separate database/tenancy design is required for multiple services/workers or other businesses. |
| **Before customer orders: operational commitments** | A bot promises the last item twice, confirms unpaid orders or invents delivery availability | Build reservation, payment, refund/cancellation and delivery state machines; approve public catalog and freshness rules; test handoff to staff. Explicitly authorize channels and spend. |

The existing `beforeunload`/retry protections are useful but not an offline queue. The roadmap is a guide with explicit requirements, not an installed background task engine. The founder's competitor observations remain hypotheses until compared with real sales and product evidence.

## Suggested domain arrangement

Keep `thesausageguy.shop` as the public customer site. Put the separate private app at `ops.thesausageguy.shop`, subject to the owner's final hostname/host selection. An ordinary Admin link can connect the sites later; merging authentication or internal data into the public Next.js site is unnecessary for the pilot.

Read-only DNS inspection on 9 September 2026 returned Porkbun nameservers (`fortaleza`, `maceio`, `salvador`, `curitiba.ns.porkbun.com`) and a Vercel DNS target for `www`. The public site's README also describes Vercel deployment. This verifies routing clues, not access to either account. The missing `SAUSAGE/PROJECT_STATE.md` path was not treated as evidence.

Porkbun supports a subdomain in the Host field of a DNS record; no second domain registration is needed for this arrangement. A server that stores the database and files is still needed. [Porkbun DNS instructions](https://kb.porkbun.com/article/231-how-to-add-dns-records-on-porkbun), [Caddy HTTPS prerequisites](https://caddyserver.com/docs/automatic-https).

No DNS records, related repositories, production services, AI spending, or customer channels were changed in this review.
